# Pigcoder Design Revamp Plan

## 目标

本计划用于约束 Pigcoder 官网的视觉改版方向。改版参考 `docs/plans/openrouter.ai-DESIGN.md` 中的设计原则，但不复制 OpenRouter 的品牌视觉、配色结果或页面结构。

本次改版目标是将现有页面从“强玻璃拟态 + 多光晕 + 深蓝金色科技感”收敛为更清爽、更专业、更适合开发者阅读和决策的 SaaS 官网风格，同时保留 Pigcoder 自身品牌识别。

## 改版原则

### 保留 Pigcoder 的品牌识别

- 保留 Pigcoder 的产品定位：稳定高速的 AI 编程中转站。
- 保留现有页面的信息架构：首页、文档页、价格页。
- 保留控制台入口、API 接入说明、CLI 工具配置、价格说明等核心内容。
- 保留深蓝、金色、绿色作为品牌基础色，但降低同时出现的强度。
- 保留首页的 AI 科技感，但减少非必要装饰。

### 参考 OpenRouter 的设计方法

- 使用更克制的背景和更高的留白比例。
- 用统一组件系统管理按钮、卡片、导航、徽章、代码块和 FAQ。
- 用浅边框和轻阴影建立层级，减少重玻璃、重光晕和重阴影。
- 优先保证正文可读性和信息扫描效率。
- 让交互状态清晰，包括 hover、active、focus-visible 和 disabled。
- 移动端保持单列、清晰、触控友好。

### 不照抄 OpenRouter

- 不直接替换为 OpenRouter 紫色主品牌。
- 不把页面改成完全白底极简，避免丢失 Pigcoder 的科技感。
- 不复制 OpenRouter 的具体组件结构、文案结构或布局细节。
- 不为了相似度牺牲 Pigcoder 当前内容和转化路径。
- 不引入新的复杂框架或构建流程，除非后续明确决定工程化升级。

## 视觉方向

最终风格应接近：

> Pigcoder 2.0：清爽、专业、开发者友好的 AI 基础设施 SaaS 官网。

核心关键词：

- Clean SaaS
- Developer-first
- Subtle tech
- High readability
- Light surface
- Structured cards
- Focused CTA
- Brand retained

## 颜色策略

### 品牌色使用

当前品牌色继续保留，但使用方式需要收敛：

- 深蓝：用于品牌、标题重点、导航、深色模块和页脚。
- 金色：用于主 CTA、高价值提示、重点强调，不再大面积铺开。
- 绿色：用于成功、可用性、稳定性、充值按钮等正向状态。

### 背景策略

- 页面主体优先使用白色、浅灰、低饱和浅蓝灰背景。
- Hero 区可以保留深色或轻渐变，以维持品牌冲击力。
- 普通内容区减少大光晕和强 blur。
- 文档页优先使用清爽阅读背景，不使用强营销式背景。

### 状态色策略

- 成功状态使用绿色。
- 警告状态使用金色或橙色，但必须克制。
- 错误状态使用红色。
- 链接和 focus 状态优先使用品牌金色或深蓝，具体实现需统一。

## 字体与排版

### 字体

- 正文继续使用 Inter。
- 标题可以继续使用当前字体，也可以收敛到 Inter，但必须全站一致。
- 如果保留 `Space Grotesk`，只用于 Hero 或少量品牌标题，不用于大量正文。

### 层级

- H1 保持强视觉层级，但移动端必须降低字号。
- H2 用于主要区块标题。
- H3 用于卡片标题和文档小节。
- 正文优先保证 `line-height` 和可读性。
- 辅助说明文字使用灰色，但必须满足基本对比度。

## 组件策略

### 按钮

统一按钮系统，至少包含：

- Primary Button：主 CTA，优先用于“立即开始”“立即充值”“前往控制台”。
- Secondary Button：次 CTA，优先用于“查看文档”等辅助动作。
- Ghost Button：导航、轻量操作、文档辅助链接。

要求：

- 高度统一，移动端不低于 44px。
- 圆角统一，避免每处随意设置。
- hover、active、focus-visible 状态必须明确。
- 避免继续堆叠过长且不一致的 Tailwind class。

### 卡片

统一卡片系统，至少包含：

- Standard Card：普通功能、FAQ、文档提示。
- Feature Card：首页重点能力和模型展示。
- Pricing Card：价格套餐。
- Doc Panel：文档页正文容器。

要求：

- 以浅边框和轻阴影为主。
- 只有关键卡片允许更强视觉突出。
- 减少玻璃拟态使用频率。
- hover 只做轻微上浮或边框变化，不做过度动画。

### Header

- Header 保持 56px 左右高度。
- 背景更清爽，优先白色或轻透明。
- 当前页面 active 状态需要清楚。
- 主题切换和语言切换保持可访问。
- `span` 类型的可点击控件应改为 `button`。

### Footer

- Footer 保持内容完整，但视觉上更克制。
- 链接分组清晰。
- 图标如果不可点击，不应表现为明显可点击状态。

### 文档代码块

- 代码块应提升可读性。
- copy 按钮状态应清晰。
- 协议、端点、环境变量等关键信息需要更容易扫描。

## 页面改版策略

### 首页

首页可以保留最多的品牌表现力，但需要降低视觉噪音。

重点调整：

- Hero 保留强 CTA 和产品定位，但减少光晕堆叠。
- 功能卡片从玻璃拟态转向清晰浅卡片。
- 模型覆盖区域更像数据/能力展示，而不是装饰区。
- 开发者工具箱保持 Bento 思路，但统一卡片层级和间距。
- 底部 CTA 保持强转化，但样式与首屏 CTA 统一。

### 文档页

文档页以阅读效率为第一优先级。

重点调整：

- 背景更清爽。
- 正文容器更稳定，减少透明叠层。
- 侧边栏当前状态更明确。
- 代码块和表格提高扫描效率。
- 页面不追求强营销感，优先开发者文档体验。

### 价格页

价格页应接近标准 SaaS Pricing 页面。

重点调整：

- Hero 简化。
- 套餐卡片统一高度、边框、主次层级。
- 按量付费和包月切换更清晰。
- FAQ 改善语义和可访问性。
- 充值 Modal 保持清晰流程，但补充语义和 focus 体验。

## 可访问性要求

后续修改必须关注：

- 所有可交互元素必须有清晰 focus-visible。
- 可点击的 `span` 或 `div` 应尽量改为 `button` 或语义化元素。
- FAQ 应支持键盘操作。
- Modal 应支持 Escape 关闭，并尽量管理焦点。
- 移动端触控目标不小于 44px。
- 文字颜色必须避免弱对比。
- 动画需要支持 `prefers-reduced-motion`。

## 性能与维护要求

- 不引入重型依赖。
- 不改变当前纯静态站点定位。
- 不新增构建流程，除非后续明确需要。
- 减少重复 class，优先通过 `common.css` 抽取可复用组件类。
- 保持 partial 加载机制可用。
- 避免直接双击 HTML 预览的误判，验证应使用静态服务器。

## 实施顺序

建议按以下顺序推进：

1. 更新设计 token：颜色、字体、间距、focus、motion。
2. 抽取全站组件类：按钮、卡片、容器、徽章、代码块。
3. 改 Header 和 Footer，建立全站基准风格。
4. 改首页，保留品牌冲击力但收敛装饰。
5. 改文档页，优先提升阅读性。
6. 改价格页，统一 Pricing 和 FAQ 体验。
7. 做响应式检查和可访问性修补。
8. 运行本地静态服务器做 smoke test。

## 验收标准

改版完成后应满足：

- 页面仍保持 Pigcoder 品牌识别，而不是变成 OpenRouter 复制品。
- 三个核心页面内容完整，无关键入口丢失。
- Header、Footer、CTA、卡片和按钮风格一致。
- 文档页比改版前更清晰、更易读。
- 价格页套餐信息更容易比较和行动。
- 移动端布局正常，无明显溢出。
- partial 加载正常，无控制台关键错误。
- 主题切换、语言切换、FAQ、Modal、价格卡片渲染正常。
